# 일확천금 · lotto-lab

로또 6/45 와 연금복권720+ 전 회차를 통계로 분해하고, 매주 **5,000원(로또) + 5,000원(연금)** 을
어떻게 나눠 살지 계산하고, 실제 구매 기록까지 관리하는 **정적 사이트**입니다.

> **웹에서 바로 열기 → https://ljo0527.github.io/lotto-lab/**

서버도, 빌드도, 데이터베이스도 없습니다. `index.html`·`pension.html` 이 브라우저에서
동행복권 공식 API 를 직접 호출해 전 회차를 받아오고, 결과를 브라우저에 캐시합니다.
매주 추천·채점·검증은 **GitHub Actions 가 자동으로** 계산해 커밋·배포합니다(아래 「자동화」 참고).

## 5,000원 + 5,000원 — 매주 뭘 사는가 (정직하게)

**바뀌지 않는 것: 당첨 확률.** 로또 1등은 몇 번을 고르든 1/8,145,060, 연금복권 1등은 1/5,000,000 입니다.
번호 선택으로 확률(분자)은 절대 못 바꿉니다. 아래 두 가지만 손댈 수 있습니다.

### 로또 5게임(A~E) — 인기도 낮추기 + 겹침 줄이기

1·2·3등 당첨금은 **고정된 몫을 당첨자 수로 나눠 받습니다.** 그래서 "이 번호가 얼마나 인기 있었나"를
서로 다른 두 데이터로 각각 측정해 상관 0.895를 확인했고(아래 「찾아낸 것」 참고), 인기도가 낮은(=당첨돼도
나눠 가질 사람이 적을 것으로 보이는) 조합을 고릅니다. **바뀌는 건 당첨 시 나눠 갖는 인원이지, 당첨 확률이
아닙니다.**

여기에 두 번째 축으로 **5게임끼리 번호가 겹치는 정도(≤1개)** 를 제한합니다. 개별 줄의 확률은 그대로이지만,
5게임을 하나의 묶음으로 볼 때 "이번 주에 뭐라도 하나 맞을 확률"은 겹침이 적을수록 올라갑니다.

| | 5게임 중 1개 이상 당첨(주간) | 5,000원당 기대 회수액 |
|---|---|---|
| 무작위 5게임 | **11.36%** (기준선) | 2,500원 (m=1 기준) |
| 이 저장소의 포트폴리오(겹침≤1) | **11.75%** | 검증(`validate.html`)의 최근 실측치 — 계산 시점마다 바뀜 |

「11.36% → 11.75%」는 개별 줄의 당첨 확률이 오른 게 아니라, **5줄을 서로 다르게 짜서 묶음 커버리지를
넓힌 결과**입니다. 인기도 쪽 효과는 재보정 walk-forward 기준 약 **+7%**(당첨 시 나눠 갖는 인원 기준,
확률 아님) — 최신 숫자와 신뢰구간은 항상 검증 페이지를 보세요, 이 문서엔 고정된 숫자를 박아두지 않습니다.

### 연금 5장 — 분산 vs 세트 (기대값은 같음)

연금복권720+는 **당첨금이 고정액**입니다. 2명이 당첨돼도 각자 월 700만원을 그대로 받습니다.
그래서 로또처럼 "나눠 갖는 인원"을 줄이는 레버 자체가 없습니다. 대신 5장을 **어떻게 흩어지게 살지**만
고를 수 있고, 어느 쪽을 골라도 5,000원당 기대값은 정확히 같습니다.

| 5장 구성 | 1장이라도 당첨 | 기대값 | 특징 |
|---|---|---|---|
| **분산**(끝자리 5개 모두 다름, 기본값) | **50.0%** | 3,750원 | 최대 당첨금은 낮지만(2등대) 매주 절반은 무언가 걸림 |
| **세트**(같은 번호 × 5조) | **10.0%** | 3,750원(동일) | 90%의 주는 0원이지만, 걸리면 1등+2등 4개가 겹쳐 최대 21.6억 |

기본은 **분산**입니다 — 기대값이 같은 채로 매주 당첨 확률(무언가라도)이 5배 높기 때문입니다.
번호 선택 자체(어떤 숫자를 고르는가)는 확률·기대값에 전혀 영향을 주지 않습니다. 영향을 주는 건
「5장이 서로 다른 끝자리인가, 같은 세트인가」뿐입니다.

이 규칙은 **1243회(로또)/334회(연금)부터** 적용됩니다. 그 이전 회차를 다시 계산하면(재현) 그 회차 당시의
옛 규칙 그대로 나오도록 만들어져 있습니다 — 그래야 지난주 채점과 원장이 어긋나지 않습니다.

## 이 도구가 실제로 찾아낸 것 (로또 인기도 모델)

전 회차를 다 뒤진 결과, 번호 선택으로 바꿀 수 있는 건 **딱 하나**였습니다.

| 통념 | 검정 결과 |
|---|---|
| 잘 나오는 번호가 있다 | ❌ 카이제곱 균일성 검정 통과 |
| 오래 안 나온 번호는 나올 때가 됐다 | ❌ 기하분포 그대로 (도박사의 오류) |
| 동반쌍에 패턴이 있다 | ❌ 이항분포 범위 안 |
| 추첨 순서에 신호가 있다 | ❌ 순번별 카이제곱 전부 잡음 |
| **당첨자 수는 줄일 수 있다** | ✅ **독립된 두 모델의 예측 상관 0.895** |

**모델 A · 판매 기준** — 4·5등 당첨자 수가 기대치보다 얼마나 많았나
(기대 4등 = 총판매게임수 × 11,115 / 8,145,060). 4등 지수와 5등 지수의 상관 0.92.

**모델 B · 구매방식 기준** — 1등 당첨자 중 **수동 선택 비율**이 그 시대 기준선보다 높았나.
자동은 815만 조합에 균등하게 뿌려지지만 수동만 사람이 좋아하는 번호로 몰립니다.
공식 API 의 `winType1/2/3`(자동/수동/반자동), 262회부터 974개 회차·1등 당첨자 9,174명분.

> **두 모델은 공유하는 데이터가 하나도 없습니다. 그런데 예측 상관이 0.895입니다.**

유의한 특징 일곱 개가 전부 같은 방향이었습니다. 「조합 생성」 탭의 **「최소 분배」** 전략과 이번 주
페이지의 A~E 5게임이 이 모델을 씁니다.

## 원장 — 그래서 실제로 얼마나 맞았나

「매주 추천 5게임(로또)/5장(연금)을 산다」를 과거로 되돌려(walk-forward) 그대로 굴린 실측 기록이
`검증`(`validate.html`) 과 `기록`(`record.html`) 에 있습니다. 각 회차의 추천은 **그 회차 직전까지의
데이터로만** 다시 계산합니다 — 미래를 쓰지 않습니다.

핵심만 요약하면:

- **회수율은 평균이 아니라 중앙값으로 읽어야 합니다.** 1등 꼬리 하나가 평균과 중앙값을 크게 벌립니다.
  (무작위 5게임 × 300주 기준: 평균 54.5% vs 중앙값 18.0%.)
- **모델이 실제로 예측하는 건 당첨번호가 아니라 «그 회차의 인기도»입니다.** out-of-sample R² 는
  재보정 후 약 0.37 — 실재하지만 완만합니다.
- **한 주 실적으로 규칙을 판단할 수 없습니다.** 회수금만으로 이 효과를 통계적으로 판별하려면 수백만
  주가 필요합니다(검증 페이지 3층 참고). 판단은 모델 적합도·z이득 층에서 합니다.

실측 수치(회수율, R², z이득, 보정 p)는 계산할 때마다 바뀌므로 이 문서에 고정값을 적지 않습니다 —
항상 `validate.html`을 보세요.

## 자동화

매주 계산·배포는 **GitHub Actions**(`.github/workflows/weekly.yml`)가 합니다. PC를 켜 둘 필요가 없습니다.

- **트리거** — `main` 브랜치에 push 하거나(설정 변경 등), 정해진 스케줄(연금 목 21:30·금 09:00 KST 재확인,
  로또 토 22:30·일 09:00 KST 재확인)이 되면 자동으로 돕니다. `workflow_dispatch`로 수동 실행도 됩니다.
- **하는 일** — 동행복권 공식 API 에서 로또·연금 전 회차를 받고, `index.html`/`pension.html`을 헤드리스
  크로미움으로 실제로 띄워 그 안의 함수로 이번 주 추천·지난주 채점·검증 지표·실구매 원장을 계산한 뒤,
  바뀐 `brief.html`/`brief/`/`validate.html`/`lotto-history.json`만 커밋하고 GitHub Pages 로 배포합니다.
- **`dev/**` 브랜치** — 같은 계산을 돌리되 **커밋·배포는 하지 않고** 결과 요약만 워크플로 로그에 주석으로
  남깁니다. 로직을 고칠 때 실제 사이트를 건드리지 않고 검증하는 통합 테스트용입니다.
- **PC 는 더 이상 「데이터-갱신」이나 예약 작업이 필요 없습니다.** `데이터-갱신.bat`/`update.ps1`과
  Cowork 예약 작업(`setup/triggers/*.md`)은 GitHub Actions 로 대체됐습니다. 자세한 내용은
  `setup/triggers/README.md`를 보세요 — 예약 작업을 계속 켜 둘 경우 지켜야 할 규칙이 있습니다.

## 경고

**이 도구는 예측하지 않습니다.**

- 각 회차는 독립 시행입니다. 지난 회차는 다음 회차에 아무 정보도 주지 않습니다.
- 어떤 번호를 고르든 로또 1등 확률은 **1/8,145,060**, 연금복권 1등 확률은 **1/5,000,000** 으로 동일합니다.
- 로또의 구조적 기대 회수율은 판매액의 약 50%, 연금복권720+는 5,000원당 기대값 3,750원입니다.
  장기적으로 구매액의 상당 부분은 반드시 사라집니다.

바꿀 수 있는 건 로또는 "터졌을 때 얼마를 나눠 받느냐"(당첨 인원), 연금복권은 "5장이 어떻게 흩어지느냐"
(당첨 분포)뿐입니다. 둘 다 확률이나 기대값 자체를 올리지 않습니다. 실측 숫자는 항상 `validate.html`을
보세요 — 이 문서의 어떤 숫자도 계산이 갱신되면 낡아집니다.
