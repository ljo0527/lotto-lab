# 일확천금 · LOTTO LAB

로또 6/45 전 회차(1회~최신)를 통계로 분해하고, 조합을 만들고, 등수를 시뮬레이션하고,
실제 구매 기록까지 관리하는 **단일 HTML 도구**.

> **웹에서 바로 열기 → https://ljo0527.github.io/lotto-lab/**

서버도, 빌드도, 데이터베이스도 없습니다. `index.html` 하나가 브라우저에서
동행복권 공식 API를 직접 호출해 전 회차를 받아오고, 결과를 브라우저에 캐시합니다.

## 무엇을 하는가

| 탭 | 내용 |
|---|---|
| **대시보드** | 최신 회차, 다음 추첨 D-day, 등수별 실제 확률, 고정해 둔 추천 조합 |
| **번호 통계** | 출현 빈도 + 카이제곱 균일성 검정 / 미출현 기간 / 동반쌍 / 합계·홀짝·구간·연속수·이월수 분포 |
| **추첨순서** | 공이 실제로 나온 순서. 순번별 카이제곱 검정으로 신호 유무 판정 |
| **조합 생성** | 6가지 전략 + 합계·홀짝·연속수·고정수·제외수 필터. 인쇄용 마크시트 출력 |
| **시뮬레이터** | "매주 N게임 사면 4등은 언제?" 몬테카를로 + 내 조합으로 전 회차 백테스트 |
| **내 기록** | 산 번호를 넣어두면 회차 발표 시 자동 대조, 누적 손익과 등급 달성 현황 |
| **원장** | 「매주 추천 5게임을 산다」를 300주 walk-forward 로 굴린 장부. 우연 분포와 나란히 놓고 본다 |
| **데이터** | 수집 상태, 무결성 6종 점검, JSON 내보내기/복구 |

추천은 **로또 용지 그대로** A~E 다섯 게임 한 장으로 보여줍니다(예비 F~J). 추첨 결과만 공식 색 공으로 그립니다.

## 이 도구가 실제로 찾아낸 것

전 회차를 다 뒤진 결과, 번호 선택으로 바꿀 수 있는 건 **딱 하나**였습니다.

| 통념 | 검정 결과 |
|---|---|
| 잘 나오는 번호가 있다 | ❌ 카이제곱 균일성 검정 통과 |
| 오래 안 나온 번호는 나올 때가 됐다 | ❌ 기하분포 그대로 (도박사의 오류) |
| 동반쌍에 패턴이 있다 | ❌ 이항분포 범위 안 |
| 추첨 순서에 신호가 있다 | ❌ 순번별 카이제곱 전부 잡음 |
| **당첨자 수는 줄일 수 있다** | ✅ **독립된 두 모델의 예측 상관 0.895** |

1·2·3등 당첨금은 **고정 풀을 당첨자 수로 나눕니다.** 확률(분자)은 못 바꿔도 **분모는 바꿀 수 있습니다.**

그래서 "그 번호가 얼마나 인기였나"를 **서로 완전히 다른 두 데이터로 각각** 재고, 답이 일치하는지 봤습니다.

**모델 A · 판매 기준** — 4·5등 당첨자 수가 기대치보다 얼마나 많았나.
(기대 4등 = 총판매게임수 × 11,115 / 8,145,060) 4등 지수와 5등 지수의 **상관 0.92**.

**모델 B · 구매방식 기준** — 1등 당첨자 중 **수동 선택 비율**이 그 시대 기준선보다 높았나.
자동은 815만 조합에 균등하게 뿌려지지만 수동만 사람이 좋아하는 번호로 몰립니다.
공식 API의 `winType1/2/3`(자동/수동/반자동), 262회부터 974개 회차·1등 당첨자 9,174명분.
시대별 자동 비율 변동(26~36%)은 ±60회 이동평균으로 통제했습니다.

> **두 모델은 공유하는 데이터가 하나도 없습니다. 그런데 예측 상관이 0.895입니다.**

유의한 특징 일곱 개가 전부 같은 방향이었습니다.

| 특징 | 모델 A (t) | 모델 B (t) | 방향 |
|---|---|---|---|
| 12 이하 번호 개수 | +8.27 | +4.88 | 많을수록 당첨자 ↑ |
| 번호 범위(최대−최소) | −8.21 | −16.88 | 넓을수록 당첨자 ↓ |
| 번호 합계 | −5.27 | −13.07 | 클수록 당첨자 ↓ |
| 끝수 중복 | +4.41 | +4.01 | 있을수록 당첨자 ↑ |

**주의 두 가지** — 「31 이하 개수」의 회귀계수 부호는 다중공선성 때문에 뒤집혀 보입니다.
단변량으로 보면 2개 0.892 → 6개 1.028로 올라갑니다(생일 편향은 실재).
그리고 점수 계산 시 각 특징을 **학습 데이터의 2~98 백분위로 잘라냅니다** — 안 그러면
최적화기가 모든 조합에 1과 45를 박아넣습니다(외삽).

「조합 생성」 탭의 **「최소 분배 ★」** 전략이 이 모델을 씁니다.
확률은 그대로 1/8,145,060 입니다. 바뀌는 건 당첨 시 나눠 갖는 인원뿐입니다.

## 원장 — 그래서 실제로 얼마나 맞았나 (2026-09-03 추가)

「매주 추천 상위 5게임(용지 한 장, 5,000원)을 산다」를 최근 **300주로 되돌려** 그대로 굴렸습니다.
각 회차의 추천은 **그 회차 직전까지의 데이터로만** 다시 계산합니다(walk-forward). 미래를 쓰지 않습니다.

### 나온 결과 — 포장하지 않고

| | 값 |
|---|---|
| 구간 | 940~1239회 · 300주 · 1,500게임 |
| 투입 / 회수 | 150만원 / 24만원 (회수율 **16.0%**) |
| 등수별 | 5등 38 · 4등 1 · 3등 이상 0 |
| 게임당 번호 일치 | 0.785 (우연 기댓값 0.800) |
| 무작위로 샀을 때 분포에서의 위치 | **34 백분위** |

**우연과 구별되지 않습니다.** 그리고 그게 정상입니다 — 확률은 번호로 바꿀 수 없기 때문입니다.

여기서 꼭 짚어야 할 게 하나 있습니다. 로또의 구조적 환급률 «약 50%»는 **1등 당첨금이 만드는 값**입니다.
1,500게임에서 1등이 한 번이라도 나올 확률은 **0.018%** 입니다.
그래서 무작위 5게임 × 300주의 **평균 회수율은 54.5%**지만 **중앙값은 18.0%** 입니다.
평균은 거의 아무도 겪지 않습니다. 실제로 겪는 값은 중앙값 쪽입니다.

### 모델은 실제로 무엇을 맞히나 — 그리고 원래 숫자는 틀렸습니다

회수율은 표본이 이래서는 모델 성능 지표가 될 수 없습니다. 모델이 **실제로 예측하는 양**을 따로 쟀습니다:
매 회차 실제 당첨번호의 분배지수 예측 vs 그 회차의 실제 4·5등 초과배수, out-of-sample 300개.

| 지표 | 값 |
|---|---|
| 상관 (예측 vs 실제) | 0.613 |
| **재보정 전 R²** | **−0.296 — 순진 예측(항상 평균)보다 나빴다** |
| 재보정 후 R² (확장창 walk-forward) | **0.365** |
| 평균오차 | 0.0299 vs 순진 예측 0.0385 (**22% 개선**) |
| 재보정 기울기 | 0.0327 / 1σ |

방향은 맞았는데 **폭이 과했습니다.** 쌓인 기록으로 기울기를 다시 재 분배지수를 재보정했습니다.
선형 변환이라 **순서가 바뀌지 않으므로 추천 조합은 그대로**이고, 표시되는 숫자만 정직해집니다.

두 모델(판매 기준·구매방식 기준)에 서로 다른 가중을 줘 봤지만 지금의 «평균 결합»보다 나아지지 않았습니다
(R² 0.363 vs 0.365). **그래서 건드리지 않았습니다.**

### 실측 효과 크기

재보정된 기울기로 계산하면, 추천 상위 5게임의 이득은 **약 +7%** 입니다.
이전에 적어 둔 «10~15%»는 재보정 전 계수로 계산한 값이라 **과대평가였습니다.**
1등에 당첨됐을 때 나눠 갖는 인원이 그만큼 적을 것으로 «측정»된다는 뜻이고,
당첨될 **확률**과는 아무 관계가 없습니다.

원장은 새 회차가 나올 때마다 한 줄씩 덧붙고(1회 추가에 약 0.1초), 재보정 표본도 매주 하나씩 늘어납니다.

## 데이터 출처

**당첨번호 · 1~5등 당첨자수 · 1게임당 당첨금 · 총판매액 · 1등 자동/수동/반자동 구성비**
동행복권 공식 엔드포인트 `/lt645/selectPstLt645InfoNew.do`
(2026년 사이트 개편으로 예전 `common.do?method=getLottoNumber` 는 폐기됨)

**추첨순서(공 나온 순서)** — 공식 데이터에 **없습니다.**
공식 API의 `tm1~tm6WnNo` 는 순서처럼 보이지만 전부 오름차순 정렬값입니다.
이 도구의 순서 데이터는 방송 기록 아카이브 수집분이며, 전 회차에 대해
**6개 번호 집합과 보너스가 공식 데이터와 100% 일치함을 검증**했습니다.

| 구간 | 상태 |
|---|---|
| 1~396회, 468~1238회 | 검증됨 (아래 개별 회차 제외) |
| **397~467회** | **신뢰 불가** — 71회 연속 전부 오름차순 = 실제 순서가 아닌 자리표시자 |
| 626·635·637·642·643·645·652·655·664·666~670·756·824 | 판정 보류 — 오름차순이라 구분 불가 |

## 데이터가 끊기지 않는 3중 안전망

1. **브라우저 자체 수집** — 페이지를 열 때마다 최신 회차만 증분으로 받아 캐시 *(기본)*
2. **주간 자동 갱신** — 일요일 09:00 KST, `lotto-history.json` 스냅샷 갱신
   (`.github/workflows/update-data.yml` + Cowork 예약 작업)
3. **`데이터-갱신.bat`** — PC에서 수동 전량 재수집

세 경로 중 하나만 살아 있으면 데이터는 유지됩니다.

## 경고

**이 도구는 예측하지 않습니다.**

- 각 회차는 독립 시행입니다. 지난 1,238회는 다음 회차에 아무 정보도 주지 않습니다.
- 어떤 6개를 고르든 1등 확률은 **1/8,145,060** 으로 동일합니다.
- 로또의 구조적 기대 회수율은 판매액의 **약 50%** 입니다. 장기적으로 구매액의 절반은 반드시 사라집니다.

바꿀 수 있는 건 "만약 터졌을 때 얼마를 받느냐" 하나뿐이고, 그것도 **원장으로 실측해 약 +7%** 입니다.
