# 학습 장부 규격 (`learn-1`)

기록 › «낙첨 분석 · 학습 실험실» 의 계산 규격. 코드와 이 문서가 다르면 코드(`scripts/learn-ledger.mjs`)와 `scripts/check-learn.mjs` 가 기준이다.
표기: 사실 `[근거: 파일]` · 추론 `[추론]` · 불확실 `[확인 필요]`. 화면 숫자는 매주 바뀌므로 이 문서에는 고정 실적을 적지 않는다.
일지 틀은 매매 일지(`docs/trade-ledger.md`, CLAUDE.md 규칙 15)와 같다.

## 1. 무엇이고 왜 만들었나

- **낙첨 분석**: 이번 주 추천 10줄(`rec`)이 «같은 주 무작위 대조군»보다 뚜렷이 나쁜지 본다. 로또는 대부분의 주가 0줄이라 «떨어진 것»만으로는 운인지 버그인지 알 수 없다. 대조군의 실제 결과와 견줘 **버그만 가려낸다**.
- **관문 있는 학습 실험실**: 후보 신호 4개(`hot` `cold` `gap` `repeat`)를 **추첨 전에 사전 등록**하고 추첨 뒤에 채점한다. 52주 이상 쌓이고 대조군의 가장 위쪽 끝에 들 때만 «채택 조건 충족» 을 표시한다.
- 둘은 **하나의 append-only 장부**(`brief/learn-lotto.json`)에 쌓는다. 한 회차 행에 추천 10줄과 신호별 10줄이 함께 얼려진다.
- **«채택» 은 상태 표시와 CI 알림(`::notice`)까지다.** 추천 코드(`portfolioPick`·`PORTFOLIO_RULES`)를 자동으로 바꾸지 않는다 — 반영은 소유자 결정이다.
- 어느 줄이든 당첨 확률은 같다. 이 장부는 확률을 바꾸지 않는다. 앞날 예측은 하지 않는다.
- 화면의 기준선은 **무작위 대조군의 실제 결과**(순위·범위)뿐이다. 이론값(기대값·σ·p값·몬테카를로·정확 확률)은 화면에 두지 않는다(규칙 9). 검증기·JSON 내부의 정수 비교는 제한이 없다.

| `docs/learn-ledger.md` | 이 문서 |

## 3. 모델

모든 신호 계산은 `past(D,t)` = 1..t-1 회차만 읽는다(t 이상을 읽으면 `RangeError`). 채점만 `D[t]` 를 본다. 결정 함수에서 `Math.random`·`Date` 를 쓰지 않는다. `Date` 는 `generated`·`made`·`gradedAt` 기록과 마감 계산(`Date.UTC`·`Date.parse`)에만 쓰고, 시험용으로 `--now <ISO>` 를 받는다.

### 3.1 자료·줄·기본 식

- `D[r] = {n:[6 오름차순], b:보너스, date:"YYYYMMDD"}`. 입력은 `lotto-history.json` 의 `draws` 이고 `1..latest` 가 연속이어야 한다. 구멍·중복·형식 오류면 계산하지 않는다(`exit 1`, 쓰기 없음).
- **줄** = 1..45 에서 서로 다른 6개, 문자열 `"a,b,c,d,e,f"`(오름차순). 맞힌 개수 `m` = 줄 ∩ 당첨 6개(보너스 제외). 보너스는 `bo`(0/1)로 따로 적는다(5개+보너스 = 2등 구분용).
- **«맞힌 줄»** = `m ≥ MIN_HIT(3)`. 한 주의 점수 `g3` = 그 주 10줄 중 맞힌 줄의 수(0~10).
- 난수: `mulberry32(seed)`(`a=(a+0x6D2B79F5)>>>0; t=imul(a^(a>>>15),1|a); t=(t+imul(t^(t>>>7),61|t))^t; return ((t^(t>>>14))>>>0)/2^32`).
  - 신호 시드 `seed(t,salt) = (imul(t,0x9E3779B1) ^ salt) >>> 0`. 소금은 `CONF.SALT` 한 곳(`hot` `cold` `gap` `repeat`).
  - 대조군 시드 `seedCtrl(t,j) = (imul(t,0x9E3779B1) ^ imul(j,CONF.CTRL_MUL) ^ CONF.SALT.ctrl) >>> 0`, `j = 1..R`. 신호 대조군 시드 `seedCtrlPool(t,j) = (seedCtrl(t,j) ^ CONF.SALT.ctrlPool) >>> 0`.

### 3.2 신호 4개 (사전 등록 · 정수 연산 · 동점은 작은 번호 우선)

`cnt[n]` = 직전 `W=50`회(`t-50..t-1`)에서 번호 `n` 의 출현 수(보너스 제외). `last[n]` = 1..t-1 에서 `n` 이 마지막으로 나온 회차(한 번도 없으면 0).

| 신호 | 점수(앞 순서) | 풀 |
|---|---|---|
| `hot` 자주 나온 번호 | `cnt` 큰 순 | 상위 15개 |
| `cold` 적게 나온 번호 | `cnt` 작은 순 | 상위 15개 |
| `gap` 오래 쉰 번호 | `last` 작은 순(가장 오래 안 나온 순) | 상위 15개 |
| `repeat` 직전 번호 다시 | 직전 회차(`t-1`) 6개 먼저, 그다음 `cnt` 큰 순 | 직전 6개 + 9개 = 15개 |

- 모든 정렬의 마지막 동점 처리는 번호가 작은 쪽이 앞이다. 풀은 번호 오름차순으로 저장한다(`sig.<s>.pool`).
- **줄 10개**: `rng = mulberry32(seed(t, salt[s]))`. 줄마다 `a = 풀 복사본(15개)`, `i=0..5` 에 대해 `j = i + floor(rng()*(15-i)); swap(a[i],a[j])` 하고 앞 6개를 오름차순으로 적는다. 같은 줄이 이미 있으면 버리고 다시 뽑는다(서로 다른 10줄). 풀 15개에서 나올 수 있는 조합은 5,005 개라 끝난다.

### 3.3 무작위 대조군 — 두 가지 (비교 대상의 구조에 맞춘다)

같은 주마다 `R=1000` 벌씩, **벌의 값 = 그 벌 10줄 중 맞힌 줄의 수**. 벌별 원값은 저장하지 않는다(시드로 다시 만든다). 행에는 분포(히스토그램)만 둔다.

| 대조군 | 만드는 법 | 기준선이 되는 대상 |
|---|---|---|
| `ctrl` 균등 줄 | 벌 `j` 는 `rng = mulberry32(seedCtrl(t,j))` 에서 줄 10개를 차례로 뽑는다: 줄마다 `a = [1..45]`, `i=0..5` 에 대해 `k = i + floor(rng()*(45-i)); swap(a[i],a[k])`, 앞 6개가 그 줄이다(균등 무작위·서로 다른 6개). 줄끼리 같은 줄이 나올 수 있고 확률은 무시할 만큼 작아 막지 않는다 | 추천 10줄(`gate.rec`·재현의 `rec`) |
| `ctrlSig` 무작위 풀 | 벌 `j` 는 `rng = mulberry32(seedCtrlPool(t,j))`(`= seedCtrl(t,j) ^ SALT.ctrlPool`). ① `a = [1..45]` 에서 `i=0..14` 에 대해 `k = i + floor(rng()*(45-i)); swap(a[i],a[k])`, 앞 15개를 **오름차순**으로 풀로 삼는다. ② 같은 `rng` 를 이어 써서 **신호와 똑같은 절차**(§3.2 «줄 10개»: 풀 복사본 부분 섞기·같은 줄은 버리고 다시 뽑기)로 서로 다른 10줄을 뽑는다 | 신호 4개(`gate.sig`·재현의 `sig`) |

- 재현에서 `rec`(A~E 5줄)와 견줄 때는 `ctrl` 같은 벌의 **앞 5줄**만 센다(줄 수를 맞춘다).
- **신호의 기준선을 `ctrlSig` 로 따로 두는 이유**: 신호의 10줄은 한 풀(15개 번호)에서 나온다. 풀에 그 주 당첨번호가 몇 개 들었는지에 따라 10줄이 함께 오르내려 «3개 이상 줄 수»의 주간 흩어짐이 독립 균등 10줄(`ctrl`)보다 크다. 흩어짐이 다른 대조군과 견주면 위쪽 꼬리 비율이 실제보다 작게 나와 채택이 쉬워진다(§12 시뮬: 균등 줄 대조군이면 정보 없는 신호의 거짓 채택률이 4.4%, 구조를 맞추면 1.0%). 정해진 풀의 맞힌 수 분포는 무작위 풀과 같아서, 정보 없는 신호에는 `ctrlSig` 가 정확한 기준선이다.
- 추천 10줄은 «어느 두 줄도 2개 이상 겹치지 않게» 펼친 줄이라 같은 수의 독립 무작위 줄보다 맞힌 줄 수의 흩어짐이 작다 `[추론]` — `ctrl` 이 더 넓게 흩어지므로 경보 쪽에서는 보수적(오경보가 줄어드는 쪽)이다. 그래서 `rec` 의 기준선은 `ctrl` 그대로 둔다(§12 시뮬: 명목 1% 에 실측 0.25%).

### 3.4 누적 대 대조군 `stat` (관문·재현 공통)

내 누적 `cum`(맞힌 줄 수의 합)과 대조군 `R` 벌의 같은 기간 누적 `c_1..c_R` 을 견준다.

| 필드 | 뜻 |
|---|---|
| `weeks` | 집계한 주 수 |
| `cum` | 내 누적 |
| `n` | 대조군 벌 수 `R` |
| `min` `med` `max` | 대조군 누적의 최솟값 · 가운데(정렬 `floor((R-1)/2)` 번째) · 최댓값 |
| `rank` | `1 + #{c_j > cum}` — 큰 값이 앞. `R+1` 이면 대조군 전체보다 낮다 |
| `tie` | `#{c_j == cum}` 같은 값인 벌 수 |
| `le` `ge` | `#{c_j ≤ cum}` · `#{c_j ≥ cum}` |
| `hist` | `[[값, 벌 수], …]` 값 오름차순 |

꼬리 비율은 `(1 + le)/(R+1)`(낮은 쪽) · `(1 + ge)/(R+1)`(높은 쪽)이고 **정수 곱셈으로 견준다**(부동소수 없음).

## 4. 산출 `brief/learn-lotto.json` (v1, `ver:"learn-1"`)

최상위 키(순서 고정): `v` `kind` `ver` `generated` `source` `conf` `rules` `summary` `journal` `checks`.

| 키 | 내용 |
|---|---|
| `kind` | `"learn-lotto"` |
| `source` | `{file, latest, count, digest}` — 입력 이력의 지문(FNV-1a 32: `Σ_{r=1..latest} "r:n1,…,n6+b;"`, `fnv:` + 소문자 16진 8자리. `trade-ledger` 와 같은 규격) |
| `conf` | `CONF` 그대로 |
| `rules` | `RULES` 그대로 `[{ver, from, signals[]}]` — 덧붙이기만 |
| `summary` | `{next, live:{done,late,counted,pending}, gate, replay}` — **매 실행 다시 계산하는 파생값** |
| `journal` | `{from, missed[], rows[]}` — §5. 행은 **한 줄에 한 행** |
| `checks` | 이번 실행의 계수기 `{kept, added, graded, pendingMismatch[], regradeMismatch[]}` |

일지 행(pending): `{r, ver, status:"pending", made, basedOn, inputDigest, rec?:{lines[10]}, sig:{hot:{pool[15],lines[10]}, cold, gap, repeat}}`.
채점되면(done) `drawDate`·`late`·`res`·`gradedAt` 이 **덧붙는다**: `res = {n[6], bonus, rec?:{m[10],bo[10],g3}, sig:{<신호>:{m,bo,g3}}, ctrl:{n:R, h[11]}, ctrlSig:{n:R, h[11]}}`. `ctrl.h[k]` = 그 주 균등 줄 대조군 `R` 벌 중 맞힌 줄이 `k` 개인 벌의 수(추천 10줄의 기준선), `ctrlSig.h[k]` = 같은 주 무작위 풀 대조군(§3.3)의 같은 분포(신호의 기준선).

- 이 판(`learn-1`)의 `conf.SALT.ctrlPool`·`res.ctrlSig` 는 첫 일지 행을 쓰기 전에 넣었다(커밋된 행이 없어 `VER` 은 그대로). 이후에는 §11 규칙을 따른다.
- 쓰기: 임시 파일 → rename. LF·UTF-8. 직렬화 뒤 되읽어 같은지 확인하고 **쓰기 직전에 1MB 미만**인지 본다. `$GITHUB_OUTPUT` 에 `wrote=true|false`.
- 멱등 비교에서 빼는 필드: `generated`, `journal.rows[].made/gradedAt`, `checks`.
- 크기: 한 주에 약 2.0KB 늘어난다(추천 줄이 있을 때, 합성 52주 실측: 평균 1,956B · 최소 1,871 · 최대 2,050). 1년 뒤 약 108KB(첫 주 5.7KB 포함), 1MB 에는 약 9~10년 뒤 닿는다 `[추론]`. 닿기 전에 §11 의 «장부 갈아타기» 를 한다.

## 5. 일지 규칙 (append-only)

| 번호 | 규칙 |
|---|---|
| J1 채점 | `r ≤ latest` 인 pending 은 done 으로 바꾼다. `late = made ≥ 추첨일 11:00Z`(= 20:00 KST, `CONF.CUTOFF_UTC_H`). late 행은 관문 집계에서 뺀다 |
| J2 빠진 주 | 마지막 일지 회차+1 … latest 사이에 행이 없으면 `missed[]` 에 적는다. **소급해서 만들지 않는다** |
| J3 새 제시 | `latest+1` 행이 없으면 pending 으로 추가한다. `ver = ruleFor(r).ver`, `inputDigest` = 1..latest 지문, `rec` 는 추천 요약의 `lotto.next === r` 일 때만 넣고 아니면 `rec` 없이 쓰고 `::warning` |
| J4 동결 | 같은 `ver` 의 기존 pending 은 다시 계산해 대조만 한다(신호·`rec`·`inputDigest`). 다르면 `::warning` + `pendingMismatch`, **처음 값을 유지**한다 |
| J5 재채점 | done 행은 매번 다시 채점해 대조만 한다. 다르면 `::warning` + `regradeMismatch` |
| J6 불변 | 행 삭제·재정렬 없음, done 행 바이트 불변. `journal.from` 은 처음 값으로 고정 |
| 역행 가드 | `latest` 가 done 최대 회차보다 작거나 pending 회차가 `latest+1` 보다 크면 쓰지 않고 `wrote=false` 로 exit 0 + `::warning` |
| 구멍 | 이력에 구멍·형식 오류가 있으면 `exit 1`, 출력 파일을 건드리지 않는다 |
| 기존 파일 보호 | 기존 out 이 깨졌거나 모양이 다르면 `exit 1`, 덮어쓰지 않는다 |

- **`rec` 가 없는 행**: 추천 요약이 그 회차 것이 아닐 때(CI 순서·요약 실패) 생긴다. 한 번 `rec` 없이 얼린 pending 에는 나중에 `rec` 를 끼워 넣지 않는다(얼린 뒤 수정 없음). 그 주는 낙첨 분석 집계에서 빠진다.
- **`RULES`**: `{ver, from, signals[]}` 덧붙이기만. **신호를 더할 때** 새 항목(`from` = 시작 회차, `signals` = 늘어난 목록)을 더하고 `VER` 을 올린다. 이미 쓴 행의 `ver` 로 옛 규칙이 남고, 새 신호는 옛 행에 없으니 주 수가 0부터 쌓인다.
- **같은 이름 신호의 정의는 바꾸지 않는다**: 신호·대조군의 정의 상수(`W` `POOL` `LINES` `MIN_HIT` `CTRL_MUL` `R` 과 이미 있는 `SALT.*`)와 점수식은 모든 행에 똑같이 적용되는 한 벌이다(행마다 상수를 따로 두지 않는다). 바꾸면 옛 행을 새 정의로 다시 계산해 L2·L4 가 실패하고, 정의가 다른 행이 한 누적(관문)으로 합쳐지는 것도 막을 수 없다. 검사기 L6 이 이전 판과 이 상수들이 다르면 오류로 막는다. 바꾸고 싶으면 **새 이름의 신호로 더하거나**(옛 정의는 그대로 두고 옛 신호는 그대로 쌓거나 `signals` 에서 뺀다) **장부를 갈아탄다**(§11).

## 6. 관문 (live = done 이고 late 가 아닌 행) — 매 실행 다시 계산

경보·채택은 일지에 박제하지 않는 **파생값**이다(`summary.gate`). 같은 일지로 언제든 다시 계산된다.

### 6.1 낙첨 분석 (`gate.rec`)

대상: `rec` 가 있는 live 행. 누적 `cum` = 그 행들 `res.rec.g3` 의 합, 대조군 누적 `c_j` = 같은 주들의 **균등 줄 대조군(`ctrl`)** `j` 벌 값의 합.

| 상태 | 조건 |
|---|---|
| `hold` 판단 보류 | `weeks < ALARM_MIN_WEEKS(26)` 또는 대상 주 없음 |
| `alarm` 경보 | `weeks ≥ 26` 이고 `(1+le)·ALARM_P[1] ≤ ALARM_P[0]·(R+1)`(낮은 쪽 꼬리 비율 ≤ 1/100) |
| `inside` | 그 밖 |

- 상태는 이 셋뿐이다. 대조군 위쪽 바깥(`cum > max`)은 낙첨 분석(버그 가려내기)에 정보 가치가 없어 따로 두지 않는다. 화면은 `inside` 이면서 `cum > max` 일 때만 태그를 «대조군 범위 안» 대신 중립색 «경보 없음» 으로 보여, 범위 밖인데 «범위 안» 이라고 적는 일이 없게 한다(순위·범위 숫자는 그대로 같이 보인다).
- `alarm` 이면 `gate.alarm = true` 와 `::warning title=낙첨 분석::… 버그 의심` 을 낸다. 화면 문구는 «떨어지는 주가 대부분인 것이 정상 — 대조군과 비교해 버그만 가려냄».

### 6.2 학습 실험실 (`gate.sig.<신호>`)

대상: 그 신호가 있는 live 행(신호별로 주 수가 다를 수 있다). 대조군 누적은 같은 주들의 **무작위 풀 대조군(`ctrlSig`, §3.3)** 값의 합이다 — 신호의 10줄과 같은 구조라서 정보 없는 신호에 정확한 기준선이 된다. 같은 이름 신호는 정의가 바뀌지 않으므로(§5) 그 신호가 있는 모든 live 행이 한 누적이다. 새 신호는 옛 행에 없어 0주부터 쌓인다.

| 상태 | 조건 |
|---|---|
| `hold` | `weeks < ADOPT_MIN_WEEKS(52)` 또는 주 없음 |
| `adopt` 채택 조건 충족 | `weeks ≥ 52` 이고 `(1+ge)·ALPHA[1]·신호수 ≤ ALPHA[0]·(R+1)` (상위 꼬리 비율 ≤ α/신호 수, α = 1/20, 본페로니) |
| `none` 채택 없음 | 그 밖 |

`adopt` 가 하나라도 있으면 `gate.adopted` 에 이름을 모으고 `::notice title=학습 실험실::신호 … 채택 조건 충족 … 추천 반영은 소유자 결정입니다` 를 낸다. 코드는 바뀌지 않는다.

## 7. 돌아보면(사후) 재현 (`summary.replay`)

- 범위: 최근 `REPLAY=300` 회(`latest-299 … latest`). 각 회차 `r` 에 대해 4신호를 `past(D,r)` 로만 만들어(walk-forward) 채점한다.
- 신호의 대조군은 관문과 같은 무작위 풀 대조군(`ctrlSig`)이다.
- `rec`: 모의 원장(`brief/sim-lotto.json`)의 범위 안 done 행 A~E **5줄**. 대조군은 균등 줄 대조군(`ctrl`)의 같은 벌 앞 5줄로 맞춘다. 모의 원장이 없거나 범위 안 행이 없으면 `rec: null`.
- 요약 = §3.4 `stat`(신호별·`rec`) 와 `{label:"돌아보면(사후)", from, to, rounds, lines, recLines}`. **회차별 원자료는 저장하지 않는다.**
- 화면에서는 반드시 «돌아보면(사후)» 라벨을 단다. 결과를 안 뒤에 계산한 표라 관문(경보·채택)에는 쓰지 않는다 — 관문은 추첨 전에 얼린 live 행만 본다.

## 9. CI 와 로컬 실행

CI(`weekly.yml`, 두 사본 `.github/workflows/` · `setup/workflows/` 가 같아야 한다): 매매 일지 단계 바로 뒤에 `학습 장부`(id `learn`, `continue-on-error`) → `학습 장부 독립 검증`(id `checklearn`, `learn` 이 `wrote=true` 일 때) → `학습 장부 검증 실패 시 되돌림`(`checklearn` 실패 시 `brief/learn-lotto.json` 을 HEAD 것으로 복원, HEAD 에 없으면 지움 — 잘못 쓰인 일지가 한 번 커밋되면 다음 주에 그 상태가 기준이 되어 굳는다), 끝쪽 `학습 장부 실패 표시`. 학습 장부는 **추천 요약(`brief/latest-summary.json`)을 쓰는 `주간 브리핑` 단계 뒤**여야 `rec` 가 얼려진다(매매 일지 단계 자리면 만족).

독립 검증 단계의 명령은 **`--prev-git HEAD` 를 꼭 붙인다**: `node scripts/check-learn.mjs --root . --file brief/learn-lotto.json --history lotto-history.json --prev-git HEAD`. 이 옵션이 없으면 L6(append-only)이 «생략» 되고 L3 도 «이번에 새로 얼린 행» 을 가려내지 못해 `rec` 누락·변조가 경고로만 남는다. 이전 판을 읽지 못하면 오류다(첫 실행처럼 HEAD 에 파일만 없는 경우만 «생략»).

로컬(Git Bash, `N=.lab/bin/node`; 쓰기는 `.lab/out-learn/` 아래만):

```
$N scripts/learn-ledger.mjs --history lotto-history.json --summary brief/latest-summary.json --sim brief/sim-lotto.json --out .lab/out-learn/brief/learn-lotto.json --now <마감 전 ISO>
$N scripts/check-learn.mjs --root . --file .lab/out-learn/brief/learn-lotto.json --history lotto-history.json --summary brief/latest-summary.json --sim brief/sim-lotto.json --prev-git HEAD
```

두 번째 판부터는 이전 출력 사본을 `--prev <파일>` 로 줘서 같은 대조를 한다(시험 폴더는 git 판이 없다).

- **`--out` 을 빼면 기본값 `brief/learn-lotto.json`(추적 일지)에 이어 쓴다.** 처음부터 시험하려면 시험 폴더의 파일을 지운다.
- 합성 시험: 이력 사본에 가짜 다음 회차를 붙이면 그 회차는 done, 그다음이 pending 이다. 이력에서 한 회차를 지우면 exit 1 이고 출력 파일은 그대로다.

## 11. 바꿀 때 · 고장났을 때

- **상수 변경**: 신호·대조군의 정의 상수(`W` `POOL` `LINES` `MIN_HIT` `CTRL_MUL` `R` 과 이미 있는 `SALT.*`)와 점수식은 같은 이름 신호가 있는 동안 바꾸지 않는다(§5 — 옛 행이 새 정의로 다시 계산돼 L2·L4 가 실패하고, 정의가 다른 행이 한 누적으로 합쳐진다. L6 이 오류로 막는다). 바꿔야 하면 **새 이름의 신호로 더하거나 장부를 갈아탄다**(아래). 경보·채택 임계(`ALARM_*` `ADOPT_*` `ALPHA` `REPLAY` `SIM_LINES`)는 파생값에만 영향을 주므로 `VER` 올림 + `RULES` 덧붙임 + `check-learn` 의 같은 상수(독립 구현이라 따로 고친다) + 이 문서.
- **새 신호 추가**: `CONF.SALT` 에 소금, `signalPools` 에 점수 정의, `RULES` 새 항목(`from`, 늘어난 `signals`)과 `VER` 올림, `check-learn` 의 `expectedPools`·`CONF.SALT`·`RULES`, 화면 `LEARN_SIGS` 이름, 이 문서 §3.2. 본페로니의 신호 수가 늘어 기준이 엄격해진다. 새 신호는 옛 행에 없어 주 수가 0부터 쌓인다.
- **경보가 떴다**: 운일 수도 있지만 대조군 하위 1% 는 흔치 않다. 순서대로 본다 — ① `check-learn` 통과 여부 ② `brief/latest-summary.json` 의 `picks`(10줄·서로 다른 6개·1..45) ③ 추천 생성 코드의 최근 변경 ④ 이력 채점과 줄 형식. 이 장부는 추천을 바꾸지 않는다.
- **채택 알림이 떴다**: 상태 표시일 뿐이다. 소유자가 «반영한다» 고 정하면 그때 추천 코드를 따로 바꾼다(그 변경은 장부 밖 — 새 `VER` 로 새 신호를 등록해 앞으로의 성적을 다시 쌓는다).
- **`check-learn` 이 CI 에서 실패**: 되돌림 단계가 일지를 HEAD 것으로 복원한다(커밋되지 않음). 로컬에서 같은 명령으로 재현하고 오류의 `L<번호>` 를 본다.
- **과거 이력이 정정됐을 때(장부가 매주 멈춘다)**: 생성기는 J4·J5 로 `::warning` 만 내고 처음 값을 유지하지만(규칙 7), `check-learn` 은 같은 상황을 **실패**로 본다 — L1·L2 의 `inputDigest`·신호 불일치, L4 의 채점 불일치, L6 의 «이력 정정 감지». 그러면 CI 되돌림이 장부를 HEAD 로 복원하므로 새 회차가 쌓이지 않고 매주 «학습 장부 실패 표시» 가 뜬다(경고가 아니라 의도된 정지다 — 정정이 맞는 값인지 사람이 확인해야 한다). 수리 절차: ① `git log -p lotto-history.json` 으로 바뀐 회차를 찾는다. 실수로 바뀐 것이면 이력을 원래대로 되돌리는 것이 먼저다. ② 정정이 맞으면 소유자 승인 뒤 **장부를 갈아탄다**: 옛 파일을 `brief/learn-lotto-<연도>.json` 으로 보관하고(새 추적 파일 1MB 미만, CI 가 검사하지 않는 보관본) `brief/learn-lotto.json` 은 지운다. 다음 실행이 `journal.from` 을 새로 잡아 쌓는다(관문 주 수가 0부터 — 소유자와 먼저 정한다 `[확인 필요]`). 옛 행을 고쳐 쓰지는 않는다(append-only).
- **장부 갈아타기(1MB 근처)**: `brief/learn-lotto.json` 을 `brief/learn-lotto-<연도>.json` 으로 보관하고(추적 파일 새로 1MB 미만) 새 파일은 `journal.from` 부터 새로 쌓는다. 이때 관문 집계(52주)가 다시 시작되므로 소유자와 먼저 정한다 `[확인 필요]`. 정의 상수를 바꾸는 경우도 같다.
- 새 추적 파일은 `git add -N` 뒤 `node scripts/check-names.mjs`(추적 파일만 검사).

## 12. 남은 결정·위험

- 첫 일지 행은 첫 CI 실행의 `latest+1` 회차(1248 부터 — `RULES[0].from`)다. 52주가 쌓이기 전에는 모든 신호가 «판단 보류» 이고 «돌아보면(사후)» 표만 채워진다. 그 표를 근거로 읽지 않도록 화면에 라벨과 설명을 상시 둔다.
- `rec` 의 F~J(6~10번째)는 별도 갈래가 새로 고른다. 그 변경이 배포된 주의 pending 은 처음 값을 유지하고 J4 경고가 한 번 날 수 있다.
- 4신호가 같은 대조군(`ctrlSig`)을 공유하므로 신호끼리 독립이 아니다. 본페로니(α/신호 수)는 «대조군이 신호와 같은 구조일 때» 만 보수적이다 — 구조가 달랐던 균등 줄 대조군에서는 보수적이지 않았다(아래 시뮬). 지금은 구조를 맞춘 대조군으로 아래처럼 확인했다.
- **귀무 시뮬(채택 관문의 정직성 점검, 2026-10-27)** `[근거: 시뮬 실측 — 스크립트는 저장소에 두지 않음]`: 생성기의 진짜 대조군 코드(`ctrlWeek`·`drawLines`·`statOf`)를 불러, 정보 없는 신호(매주 무작위 15개 풀에서 같은 절차로 10줄)에 52주 채택 조건을 적용했다. 52주 합성 이력, 대조군 100세트 × 세트당 신호 1,000개(100,000회).
  - 신호 하나의 거짓 채택률: **0.97%** (명목 α/4 = 1.25%, 순열 검정의 정확 한계 12/1001 = 1.20%). 같은 신호를 균등 줄 대조군과 견주면 4.38% — 구조를 맞추기 전의 실측(명목의 약 3.5배)이 재현된다.
  - 신호 4개 중 하나라도 채택되는 비율(가족 오류율): **3.84%** (명목 α = 5% 이내). 균등 줄 대조군이었다면 16.35%.
  - 진짜 신호 4개(`hot` `cold` `gap` `repeat`)를 무작위 이력 위에서 150번(600회) 돌려 진짜 `buildGate` 로 판정: 채택 2건(0.33%). 표본이 작아 «명목 이하» 라는 방향만 확인한다.
  - 완료 기준: 신호 대조군을 바꾸는 변경은 같은 방식의 귀무 시뮬로 거짓 채택률 ≤ 1.25% 를 다시 확인한다.
- **반복 관찰 위험**: 관문은 52주 뒤부터 **매주 다시 판정**한다. 52주째 한 번만 보면 위 1.2% 안팎이지만, 52~104주 사이 한 번이라도 채택될 비율은 신호 하나당 **3.1%**(시뮬 6,000회, 대조군 40세트)로 커지고, 신호 4개로는 약 12% 까지 간다 `[추론: 신호끼리 독립에 가깝다고 본 1-(1-0.031)^4]`. 낙첨 경보도 26주 뒤부터 매주 판정하므로 한 번만 볼 때(명목 1%, 실제 추천 구조 실측 0.25%)보다 비율이 늘어난다(반복 판정 경보율은 따로 재지 않았다 `[확인 필요]`). 채택 알림은 «반영을 검토할 후보» 일 뿐 앞날 예측이 아니고, 반영은 소유자가 정한다. **소유자 결정 항목** `[확인 필요]`: ① 판정을 52주 배수 시점(52·104·156주째)에만 한다 ② 반복 관찰 횟수만큼 채택 임계를 더 엄격하게 한다(예: 상위 꼬리 ≤ α/(신호 수 × 관찰 횟수)) ③ 지금대로 두고 알림만 본다. 지금 코드는 ③이다.
