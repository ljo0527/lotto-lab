# 갈래(spread) 배치 규격 — 이번 주 추천 F~J

표기: 사실 `[근거: 파일/실행]` · 추론 `[추론]` · 불확실 `[확인 필요]`. 적용 회차: **1248회부터**(`LAYOUT_RULES[0].from`, 상수 한 곳).

## 1. 무엇이 바뀌나

- 이번 주 추천 10줄(A~J) 가운데 **A~E(1~5번째)는 그대로**다 — `portfolioPick`·`PORTFOLIO_RULES`·구매 장부(`purchases`·`sim-lotto`, 5줄)·`validate`·`backfill`·`check-sim` 은 건드리지 않았다. [근거: index.html `weeklyPicks` — A~E 를 만든 뒤에만 분기]
- **F~J(6~10번째) 5줄만 새로 고른다.** 10줄을 함께 살 때(A~E + F~J) 아래 구조가 되도록 한다.
  1. 1~45 의 **모든 번호를 쓴다**.
  2. 어느 번호도 **3번 이상** 쓰지 않는다(1~2번).
  3. **어느 두 줄도 번호 2개 이상 겹치지 않는다**(쌍 겹침 ≤ 1).
  4. 역대 1등 조합은 제외한다.
- 1247회 이하(`layoutFor(target)===null`)는 옛 `diversifyLegacy` 10줄을 **바이트 단위로 그대로** 쓴다. [근거: 1243~1247·1230·1200·1100·700회 10줄을 main 코드 결과와 대조 — 전부 동일, 아래 §7]
- 학습 실험실·당첨금 학습의 «채택»은 상태 표시와 CI 알림까지만이다. 이 규칙은 추천 코드를 자동으로 바꾸지 않는다(반영은 소유자 결정).
- 이 갈래는 **새 장부를 만들지 않는다**(추천은 회차 시드로 매번 같은 값이 재현되는 순수 함수). 그래서 일지(pending/done)·마감·`wrote` 같은 장부 규칙은 해당 없음이다.

## 2. 규칙표 — 덧붙이기 전용

```js
const LAYOUT_RULES = [
  { from:1248, name:'spread', opts:{ restarts:40, kick:4, passes:60, eps:1e-9, seed:0x5eed } }
];
function layoutFor(target){ /* from<=target 인 마지막 항목, 없으면 null(=옛 diversifyLegacy) */ }
```

- `PORTFOLIO_RULES` 와 같은 원칙(C1): **과거 항목(opts 포함)을 고치지 않는다.** 이미 지난 회차를 지금 설정으로 다시 계산하면 그 주의 브리핑·검증과 어긋난다. 바꿀 때는 새 항목을 뒤에 덧붙인다(`from` 오름차순).
- `PORTFOLIO_RULES`·`portfolioPick`·`generate()`·validate 가 쓰는 `PORTFOLIO` 는 건드리지 않았고, 새 캐시 전역도 만들지 않았다(weekly-brief·backfill·validate 의 reset 목록이 그대로 맞는다). 탐색 중 쓰는 점수 캐시는 `spreadComplete` 호출 안의 지역 `Map` 이다.

## 3. 왜 이 구조가 성립하나 (구성)

A~E 를 보고 번호를 세 집합으로 나눈다. A~E 가 정상(겹침 ≤1, 어느 번호도 ≤2번)일 때:

| 집합 | A~E 에서 쓴 횟수 | F~J 에서 |
|---|---|---|
| U | 0번 | **정확히 한 번씩**(전부) |
| S | 1번 | 30−\|U\| 개를 골라 한 번씩 |
| D | 2번 | 쓰지 않음 |

- F~J 끼리는 번호가 겹치지 않는다(각 번호를 F~J 에서 ≤1번). 한 F~J 줄 안의 S 번호들은 **서로 다른 A~E 줄 출신**이어야 한다(그래야 그 F~J 줄과 각 A~E 줄의 겹침이 ≤1). U 번호는 어느 A~E 줄에도 없으니 제약이 없다.
- 그러면 모든 번호가 1~2번 쓰이고(U·S·D 는 A~E 와 F~J 합쳐 최소 1번), 2번 쓰인 번호는 «D 전부 + F~J 에 넣은 S» 로 정확히 \|D\| + (30−\|U\|) = **15개**다(\|U\| = 15 + \|D\| 이므로). 같은 번호가 두 줄에만 있고 줄 쌍 겹침이 ≤1 이면 번호 하나가 겹치는 쌍 하나를 만드니 **겹침이 1인 줄 쌍도 정확히 15개**(전체 45쌍 중 30쌍은 0). [근거: 산술 + check-spread S2·S3 가 실제 산출에서 15/15 를 확인]
- 항상 자리가 있다: 한 출신 줄에서 고른 S 번호는 최대 5개(F~J 5줄에 하나씩)라, 출신이 안 겹치는 줄이 늘 남는다. U 는 남은 칸을 채운다. [추론 — 구성 증명이며 15개 회차 표본·1248 실측에서 한 번도 실패하지 않음]

## 4. 목적 함수

- F~J 각 줄의 `u = max(zOf(줄), zFloor)`(`zFloor` = `zFloorOf()`, A~E 와 같은 인기 회피 기준) 합을 **최소**로 한다. 역대 1등 조합은 +1000 벌점으로 사실상 배제한다. `zOf` 가 없으면(모델 없음) 줄마다 9 로 같아 시작 배치가 그대로 나온다.
- 위 구조는 **제약**이고 u 는 **목적**이다. 구조를 어기는 대안은 후보에 오르지 않는다(이동 규칙이 구조를 보존).

## 5. 탐색 — 결정적 지역 탐색

1. **시작(탐욕)**: 안 쓸 S 번호 15−\|D\| 개를 S 목록에서 고르게 흩어 정하고, 쓸 S 는 «출신이 안 겹치는 줄 중 S 가 가장 적은 줄»(동점은 작은 줄)에, U 는 남은 칸에 오름차순으로 돌려 넣는다.
2. **지역 탐색(최선 개선)**: 매 단계 모든 이동의 u 합 변화를 계산해 가장 큰 개선 하나를 적용한다. 이동은 둘뿐이다.
   - F~J 두 줄 사이 번호 맞바꾸기(받는 줄의 출신 제약 확인),
   - 쓰는 S 번호 ↔ 안 쓰는 S 번호.
   개선 폭이 `eps`(1e-9)를 넘을 때만 받아들이고, 동점은 먼저 본 것(작은 줄·작은 칸)이다. `passes`(60) 안에 끝난다.
3. **반복 흔들기**: 현재 최선에서 시작해 구조를 깨지 않는 이동 `kick`(4)번을 무작위로 적용하고 다시 지역 탐색, 더 좋을 때만 교체. 이것을 `restarts`(40)번 한다. 난수는 `mulberry32((target·2654435761 XOR seed)>>>0)`.
4. 끝나면 F~J 를 u 오름차순(동점은 번호 사전순)으로 F,G,H,I,J 에 놓는다.

### 결정성

- 시계·시간 예산·내장 난수를 쓰지 않는다. 반복 횟수 고정, 난수는 회차 시드, 동점은 작은 번호·작은 index. 점수 캐시의 키는 정렬된 6개 번호를 46진수로 합친 정수라 문자열 정렬·해시 순서에 기대지 않는다. 같은 입력이면 같은 출력이다. [근거: 같은 페이지에서 2회, 페이지를 새로 띄워 2회 — 1248회 10줄 동일(.lab/out-spread/new-final-1·2.json)]
- 개선 폭에 `eps` 를 둬서 기기 간 부동소수 끝자리 차이가 선택을 바꾸지 않게 했다. `zOf` 는 덧셈·곱셈·나눗셈·제곱근뿐이라 엔진 간 결과가 같다. [추론]

### 비용

- 1248회: `spreadComplete` 약 90 ms(데스크톱 Chromium), `weeklyPicks` 전체 약 90~150 ms. 시간은 대부분 서로 다른 줄의 점수 계산(약 3.5만 번)이다. 느린 휴대폰은 4~6배로 보면 1초 안이다. [추론 — 휴대폰 실측 없음]
- 최적과의 거리: 15개 회차 표본(A~E 는 각 회차 `portfolio` 규칙, 800~1248회)에서 `restarts:40,kick:4` 의 F~J 평균 u 는 300회 반복 탐색(≈최적으로 보임)보다 평균 +0.028(z 단위) 나쁘다. 1248회는 −1.4285 vs −1.4326. 시간을 4배 쓰면 차이가 0 에 수렴한다. 더 좋은 값을 원하면 **새 규칙 항목**으로 `restarts` 를 올린다(옛 항목을 고치면 안 된다).

## 6. degraded

- F~J 는 위 구성으로 **언제나 구조를 지킨다**. 구조를 못 지키는 경우는 A~E 쪽 사정뿐이다.
  - A~E 에 겹침 ≥2 가 있거나 어떤 번호가 3번 이상 쓰인 경우 → F~J 로 고칠 수 없다. 이때도 U 는 모두 F~J 에 넣으므로 «45개 번호 사용·F~J 구조»는 지켜지고, 위반은 A~E 몫으로 남는다.
  - A~E 가 «6개 서로 다른 1..45 오름차순» 5줄이 아니면 `spreadComplete` 가 null → `weeklyPicks` 가 옛 `diversifyLegacy` 로 채우고 `layout.degraded=true`.
- `layout.degraded` = `(spreadFail || used≠45 || 최대 사용 횟수>2 || maxOv>1)`(spread 일 때). legacy 는 `false`.
- degraded 면 `log('경고 · …')` 로 알리고, 화면은 구조 문구 대신 실측값(쓴 번호 N개·최대 겹침 M개·«일부 조건 미달»)을 사실 그대로 적는다. 검증기는 degraded 가 실측과 일치하는지 본다(S5).

## 7. 출력 계약

`weeklyPicks()` 반환 객체 — 기존 키(`round`·`combos`·`tries`·`portfolio`·`rule`)는 그대로, **`layout` 만 추가**:

```json
"layout": { "name": "spread", "from": 1248, "used": 45, "maxOv": 1, "pairs": 15, "degraded": false }
```

- `name` `'spread'|'legacy'`(`legacy` 는 `from:null`, `degraded:false`, 나머지는 그 10줄의 실측), `used` = 10줄이 쓴 서로 다른 번호 수, `maxOv` = 최대 쌍 겹침, `pairs` = 겹침이 1인 쌍 수.
- `brief/latest-summary.json` 의 `lotto.layout`, `brief/week.json` 의 `lotto.layout` 에 같은 객체. 기존 키는 삭제·개명하지 않았다(weekly.yml 요약이 읽는다). 옛 파일처럼 `layout` 이 없는 산출도 검증기가 «건너뜀»으로 받는다.
- 지난주 재현(`prev`)은 그 회차의 `layoutFor` 를 따른다 → 1247회 이하는 바뀌지 않는다.

## 8. 화면 문구 (규칙 9)

- 이번 주 추천 탭·`brief.html`: spread 회차의 F~J 이름표 «F~J — A~E 와 같이 10줄을 사면 45개 번호를 모두 나눠 씀 · 어느 두 줄도 번호 2개 이상 겹치지 않음». degraded 면 실측값을 적는다. legacy 회차는 «예비 F~J» 그대로.
- 확률·기대·«높인다» 류 문구와 이론값(기대값·σ·p값·몬테카를로·정확 확률)을 넣지 않았다. 구조는 사실(실측)로만 적는다. 구조 때문에 «당첨이 쉬워진다» 는 말은 하지 않는다 — 줄마다 1등 확률은 1/8,145,060 로 같다.
- 10줄의 «한 줄이라도 5등 이상» 정확 확률은 **검증기 내부 ::notice 에만** 찍고 화면·JSON 에는 쓰지 않는다.

## 9. 독립 검증기 `scripts/check-spread.mjs`

`index.html`·`rank-core.js`·`lotto-trade.js` 를 import·실행하지 않는다(규칙 10). 입력은 산출 JSON·`lotto-history.json` 뿐이고, `index.html`·`weekly-brief.mjs` 는 문구 검사용으로 글자로만 읽는다.

```
node scripts/check-spread.mjs --summary brief/latest-summary.json --week brief/week.json --history lotto-history.json
  [--root .] [--index index.html] [--src scripts/weekly-brief.mjs] [--force-check] [--prob-only] [--no-prob]
```

| 검사 | 내용 |
|---|---|
| S0 입력 | picks 10개 · week.buy 5 + spares 5 · 모든 줄 «6개 서로 다른 1..45 오름차순» |
| S1 순서 | picks[0..4]=buy, picks[5..9]=spares(줄 순서까지) · summary.next = week.round |
| S2 사용 | 1..45 모두 사용 · 번호당 1~2회 · 2회 쓰인 번호 정확히 15개 |
| S3 겹침 | 45쌍 전수 겹침 ≤1 · 겹침 1인 쌍 정확히 15 · A~E 쌍 ≤1 · F~J 끼리 0 |
| S4 이력 | 10줄 모두 역대 1등 조합 아님 |
| S5 필드 | layout.{name,from,used,maxOv,pairs,degraded} 가 실측과 일치 |
| S6 문구 | summary·week 의 모든 문자열 + index.html·weekly-brief.mjs 의 spread 문구 줄에 금지 문구(`/확률을 높\|잘 나오\|당첨 보장\|가능성이? 높\|적중률 높/`)와 이론값 낱말(기대값·표준편차·σ·p값·몬테카를로·정확 확률·이론값) 없음 |

- `layout` 이 없거나 `legacy` 면 구조 검사는 **«건너뜀» ::notice, exit 0**(문구 검사는 늘 한다). 종료 코드 0/1, 실패는 `::error title=check-spread::…`.
- `--force-check`: legacy 10줄에도 구조 검사를 강제한다(옛 10줄은 구조를 못 지키므로 exit 1 이 정상 — 정확 확률 자기 확인용). `--prob-only`: 정확 확률만 찍고 0.
- **내부 정확 확률**(::notice): C(45,6)=8,145,060 추첨을 모두 세어 «10줄 중 한 줄이라도 3개 이상» 을 낸다. 자기 확인으로 1줄(=194,130)·겹침 0 두 줄(2·194,130−400)·겹침 5 두 줄이 닫힌 식과 일치함을 확인했다. 옛 1248 게시 10줄 0.224884, spread 10줄 0.230069. [근거: 검증기 실행]
- 변형 사본 시험(겹침 2 만들기·번호 하나 빼기·번호 바꿔 누락·A~E 순서/한 줄 바꾸기·layout 거짓 필드·week 불일치·금지 문구(JSON·소스)·역대 1등과 같은 줄)은 모두 exit 1, 정상 산출은 exit 0.

## 11. CI 연결 (리드 몫 — 이 갈래에서 워크플로는 고치지 않았다)

`weekly.yml` 의 `로또 전 회차 스냅샷 (lotto-history.json)` 뒤에 `갈래 배치 독립 검증` 단계(`continue-on-error: true`, `if: steps.brief.outcome == 'success'`)와, 끝쪽 «… 실패 표시» 묶음에 `steps.checkspread.outcome == 'failure'` 조건. 두 워크플로 사본은 `diff -q`(규칙 6).
