> **2026-09 개편: 이 예약 작업들은 더 이상 필요하지 않다.**
> 계산·커밋·배포는 이제 `.github/workflows/weekly.yml`(GitHub Actions)이 push 또는 스케줄로 전부 한다
> (연금 목 21:30·금 09:00 KST, 로또 토 22:30·일 09:00 KST — 아래 두 예약 작업과 거의 같은 시각이다).
> **PC 를 켜 둘 필요가 없다.** 소유자에게 이 예약 작업들을 **끄는 것을 권장**한다.
> **끄기만 하고 삭제하지 말 것** — 실행 이력과 컴퓨터 연결이 날아간다. 이름·주기·켜기끄기는 데스크톱 승인 없이 바뀐다.

## 계속 켜 둘 경우의 규칙 (필수)

GitHub Actions 가 매주 같은 파일을 계산·커밋한다. 이 예약 작업을 계속 켜 두면 **같은 파일을 두 번
계산하게 되어 서로 다른 실행 시점의 값이 충돌**할 수 있다. 그래서 계속 켜 두더라도:

- **다음 파일을 절대 쓰거나 깃허브에 올리지 않는다**(생성 파일 전부): `brief.html`, `brief/*.html`,
  `brief/index.html`, `brief/latest-summary.json`, `brief/purchases.json`, `brief/validation.json`,
  `validate.html`, `lotto-history.json`.
- `weekly-brief.mjs`/`validate.mjs`/`fetch-history.mjs` 를 **실행하지 않는다** — 이 스크립트들의 결과물이
  바로 위 목록이다. 실행 자체가 곧 위 규칙 위반으로 이어진다.
- 대신 **이미 GitHub Actions 가 커밋해 둔 결과를 읽기만** 한다(저장소의 `brief/latest-summary.json`,
  `brief/purchases.json`, `brief/validation.json`, 또는 배포된 사이트 `https://ljo0527.github.io/lotto-lab/`)
  하고, 그 내용을 한국어로 **보고만** 한다.
- **깃허브 푸시는 사용자가 직접 하거나 GitHub Actions 가 스케줄로 한다** — 이 예약 작업은 어떤 경우에도
  커밋·푸시를 하지 않는다(과거엔 파일 생성까지만 하고 푸시는 사용자 몫이었지만, 지금은 파일 생성 자체를
  하지 않는다는 점이 다르다).
- Actions 실행이 실패했거나(빨간 X) 결과가 오래됐으면, **로컬에서 대신 계산하지 말고** 그 사실만
  보고한다. 로컬 재계산은 GitHub Actions 의 다음 실행과 다시 충돌한다.

## 적용 방법

데스크톱 앱에서 해당 예약 작업을 열고 프롬프트를 위 파일 내용으로 통째로 교체한다.
**삭제 후 재생성하지 말 것** — 실행 이력과 컴퓨터 연결이 날아간다.

## 개편 이력

### 2026-09-23 — GitHub Actions 로 계산·배포 이관

`.github/workflows/weekly.yml` 이 push·스케줄 두 경로로 전 계산(브리핑·검증·원장·데이터 스냅샷)과 커밋·
배포를 전부 맡게 되면서, 이 예약 작업들의 **원래 역할(파일 생성·커밋)은 없어졌다.** 계속 켜 둘 이유가
있다면 「이번 주에도 Actions 가 제대로 돌았는지 확인하고 요약해 알려주는」 상태 점검 용도뿐이다 —
위 「계속 켜 둘 경우의 규칙」을 따른다. `dev/**` 브랜치 push 는 같은 계산을 커밋·배포 없이 검증만 한다.
